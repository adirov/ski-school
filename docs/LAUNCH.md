# Запуск: хостинг, домен, Search Console, аналитика

Делать по порядку. Шаги 1–4 можно сделать до получения всех данных, индексацию (шаг 6) включаем только после подтверждения контента.

## 1. Хостинг

Нужен хостинг с Node.js 20+, потому что форма заявок работает на сервере.

- **Vercel** (проще всего): импорт репозитория GitHub, переменные окружения в Settings → Environment Variables, каждый коммит = новый деплой. Бесплатного тарифа хватит на старте, но для коммерческого сайта по правилам Vercel нужен тариф Pro.
- **VPS** (любой провайдер в Казахстане или за рубежом): `npm ci && npm run build && npm start` под pm2 или systemd, перед ним nginx с HTTPS (Let's Encrypt).
- **GitHub Pages** (только для показа): `npm run build:pages` собирает статическую копию, workflow `.github/workflows/pages.yml` выкладывает её при каждом push в main (Settings → Pages → Source: GitHub Actions). На Pages нет сервера, поэтому форма заявок не работает и честно об этом пишет; редиректы сделаны HTML-страницами. Для рабочего сайта нужен один из вариантов выше.
- Обычный shared-хостинг с PHP **не подойдёт**, если на нём нельзя запускать Node.js. Уточнить у провайдера.

Ограничение защиты от спама: счётчик частоты заявок хранится в памяти процесса. На одном сервере работает полностью, на Vercel (несколько экземпляров) слабее. При росте спама подключить Turnstile/hCaptcha или Redis.

## 2. Переменные окружения

Все описаны в `.env.example`. Минимум для запуска:

```
NEXT_PUBLIC_SITE_URL=https://ваш-домен
NEXT_PUBLIC_ALLOW_INDEXING=0          # 1 только на боевом домене
LEAD_FORM_SECRET=<длинная случайная строка>
LEAD_TELEGRAM_BOT_TOKEN=… и LEAD_TELEGRAM_CHAT_ID=…   (или LEAD_WEBHOOK_URL)
```

Секреты не хранить в репозитории и не пересылать в чатах.

`NEXT_PUBLIC_*` вшиваются при сборке: после изменения нужна пересборка.

## 3. Приём заявок

1. Создать бота у @BotFather, добавить его в рабочий чат, узнать chat id.
2. Вписать токен и chat id в переменные, пересобрать.
3. Отправить тестовую заявку с сайта и убедиться, что она пришла.
4. Пока канал не настроен, формы на сайте нет: вместо неё показывается запись по телефону. Форма появляется после пересборки с настроенным каналом.

## 4. Домен

1. Купить домен (например, в зоне .kz через регистратора, или .com).
2. В панели хостинга добавить домен, у регистратора прописать DNS-записи, которые даст хостинг.
3. Дождаться HTTPS-сертификата. Проверить, что `http://` и `www.` перенаправляют на один основной адрес.
4. `NEXT_PUBLIC_SITE_URL` = этот адрес, пересобрать.

## 5. Включение индексации

Сайт по умолчанию собирается в рабочем режиме (без плашек и TODO), но закрыт от поиска, пока индексацию не включили явно:

1. `NEXT_PUBLIC_SITE_URL=https://ваш-домен` (настоящий https-адрес; с localhost или example.com сборка остановится с ошибкой).
2. `NEXT_PUBLIC_ALLOW_INDEXING=1`, пересобрать.
3. Проверить: на страницах `<meta name="robots" content="index, follow">`, `/sitemap.xml` содержит страницы, `/robots.txt` ссылается на sitemap. Страницы «Спасибо», поиск и юридические тексты (пока `legal.approved: false`) остаются noindex.
4. На GitHub Pages то же самое задаётся переменными репозитория `SITE_URL` и `ALLOW_INDEXING` (Settings → Secrets and variables → Actions → Variables).

Режим `NEXT_PUBLIC_SITE_MODE=preview` нужен только для внутренней проверки: показывает примеры, черновики и TODO, всегда noindex.

## 6. Google Search Console

1. search.google.com/search-console → «Добавить ресурс» → **Доменный ресурс** → подтвердить через TXT-запись у регистратора.
2. «Файлы Sitemap» → отправить `https://ваш-домен/sitemap.xml`.
3. «Проверка URL» для главной RU и EN → «Запросить индексирование».
4. Через 1–2 недели смотреть «Страницы» (ошибки индексации) и «Основные интернет-показатели» (реальные Core Web Vitals, появляются только при достаточном трафике).
5. Яндекс Вебмастер: то же самое для аудитории из РФ и Казахстана.
6. Проверить разметку: search.google.com/test/rich-results для главной, тура и статьи.

## 7. Аналитика

1. Создать ресурс GA4 и/или счётчик Яндекс Метрики.
2. Вписать `NEXT_PUBLIC_GA4_ID` / `NEXT_PUBLIC_YANDEX_METRIKA_ID`, пересобрать.
3. Счётчики загружаются **только после согласия** посетителя в баннере.
4. События: `lead_submit`, `whatsapp_click`, `phone_click`, `booking_click`, `gyg_click`. Передаётся только тип события и id услуги/тура, без имени, телефона и текста заявки.
5. В GA4 отметить `lead_submit` как ключевое событие (конверсию).
6. В Метрике не включать Вебвизор на страницах с формой, либо исключить поля формы.

## 8. Google Business Profile

1. business.google.com → добавить компанию «Almaty Snowboard», категория близкая к «Школа сноуборда» / «Инструктор по горным лыжам».
2. **Если нет офиса, куда приходят клиенты, указать бизнес с зоной обслуживания** (Алматы, горные курорты) и скрыть адрес. Не указывать адрес курорта или чужой адрес как свой: это нарушает правила Google и приводит к блокировке профиля.
3. Телефон и сайт те же, что на сайте. Название без ключевых слов («Almaty Snowboard», а не «Almaty Snowboard сноуборд уроки дешево»).
4. Пройти подтверждение (видео или код, как предложит Google).
5. Добавить реальные фото, часы работы (сезонные), услуги с теми же названиями, что на сайте.
6. Отзывы просить у реальных клиентов после занятия, ссылкой. Не покупать и не писать отзывы за клиентов.
