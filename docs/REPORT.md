# Отчёт: Almaty Snowboard, версия для разработки (4 ноября 2026)

## 1. Что реализовано

- Next.js 15 + TypeScript, статическая генерация, RU и EN (KK подготовлен, но выключен, пока нет проверенного перевода).
- Страницы: главная, каталог с фильтром по уровню, страница тура (все поля, «Запросить доступность», необязательная ссылка на GetYourGuide), страницы услуг, «О нас», «Команда» (появится только с реальными данными), статьи с категориями, поиском, оглавлением, автором и рецензентом, датами, источниками; FAQ, контакты, условия бронирования, политика конфиденциальности (оба текста черновики), «Спасибо», настоящая 404.
- Контент отделён от кода (`content/`). Все неподтверждённые сведения помечены TODO, полный список: `npm run check:content` (84 пункта).
- Два режима: **preview** (примеры и черновики с плашками, всё закрыто от индексации) и **production** (только подтверждённое, пустые разделы скрыты).
- Форма заявки: проверка на сервере, защита от спама (токен с минимальным временем заполнения, скрытое поле, лимит частоты, защита от повторной отправки). Успех показывается только после реальной доставки в Telegram или webhook. Без канала форма пишет, что приём не подключён.
- SEO: canonical, hreflang только между существующими переводами, sitemap, robots, Open Graph, noindex для служебных страниц и черновиков, постоянные редиректы при смене адреса (`content/redirects.json`), оптимизация изображений (AVIF/WebP).
- JSON-LD (Organization, WebSite, BreadcrumbList, BlogPosting, TouristTrip) только для подтверждённого видимого контента. Нет рейтингов, отзывов, наличия мест; цена только если указана на странице.
- Аналитика GA4 / Яндекс Метрика через переменные окружения, загружается после согласия, без персональных данных.
- Контент-план из 20 тем (`docs/CONTENT-PLAN.md`) и 3 черновика статей (RU), одна из них переведена на EN.

## 2. Как запустить

```
npm install
cp .env.example .env.local
npm run dev            # http://localhost:3000
npm run build && npm start   # как на сервере
```

## 3. Где менять контент

Папка `content/`, инструкция в `docs/EDITING.md`: туры (`content/tours/*.json`), услуги, статьи (`content/articles/ru|en/*.md`), контакты и факты (`content/site.json`), FAQ, юридические тексты (`content/pages/`), фото (`public/images/` + `content/media.json`).

## 4. Данные от владельца

`docs/OWNER-DATA.md`. Главное: какие услуги реально есть, цены, контакты (какой номер верный, WhatsApp, e-mail), юрлицо, условия отмены, квалификации тренеров, свои фото.

## 5. Что подключить до запуска

Хостинг с Node.js (Vercel или VPS), домен и HTTPS, канал заявок (Telegram-бот или webhook), `LEAD_FORM_SECRET`, `NEXT_PUBLIC_SITE_URL`, проверка юридических текстов юристом, затем `NEXT_PUBLIC_SITE_MODE=production`. Подробно: `docs/LAUNCH.md`.

## 6. Что проверено и что ещё нужно

Проверено локально:
- Сборка и проверка типов TypeScript без ошибок.
- Коды ответов: редирект `/` → `/ru/`, 404 для несуществующих страниц, языков и непереведённых статей, 308 на адрес со слешем.
- Метатеги: canonical, hreflang, noindex в preview и для черновиков юридических текстов, sitemap в production содержит только индексируемые страницы.
- API формы: все ошибки (слишком быстро, валидация, скрытое поле, неверный токен, повтор, лимит частоты, канал не настроен) и успешная доставка на тестовый webhook.
- Playwright на 1440 и 390 px: нет горизонтальной прокрутки, мобильное меню и Escape, фильтр, переключатель языка, честное сообщение формы.
- Lighthouse (лабораторно, локально, preview): главная — производительность 97, доступность 100, рекомендации 100; LCP 2.2–2.7 с, CLS около 0. SEO 69 только из-за noindex в preview.

Не проверено, нужно после запуска:
- Реальные Core Web Vitals (Search Console / CrUX, нужен трафик), Lighthouse на боевом домене.
- Rich Results Test на боевых адресах.
- Реальная доставка заявки в Telegram владельца.
- Проверка на реальных телефонах (iOS Safari, Android) и скринридером.
- Юридическая проверка текстов.
- Оценку 100 во всех категориях не обещаем: лабораторные цифры зависят от хостинга, а SEO в preview занижено намеренно.

## 7. Порядок подключения

1. Хостинг → деплой в режиме preview.
2. Канал заявок → тестовая заявка.
3. Домен и HTTPS → `NEXT_PUBLIC_SITE_URL` → пересборка.
4. Владелец подтверждает контент → статусы confirmed/published → production → пересборка.
5. Search Console (доменный ресурс) → отправить sitemap → запросить индексирование главных страниц. Яндекс Вебмастер так же.
6. GA4 / Метрика → ID в переменные → пересборка → `lead_submit` как конверсия.
7. Google Business Profile как бизнес с зоной обслуживания (без выдуманного адреса).
