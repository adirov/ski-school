# Админка (CMS)

Адрес: **https://adirov.github.io/ski-school/admin/** (после подключения своего домена: `https://<домен>/admin/`).

Админка — [Sveltia CMS](https://github.com/sveltia/sveltia-cms). Сервер и база данных не нужны: админка открывается в браузере, правит файлы в `content/` прямо в репозитории GitHub, а GitHub Actions пересобирает сайт. Изменения появляются на сайте примерно через 2–3 минуты после «Сохранить».

Почему Sveltia, а не Decap/Tina: сайт лежит на GitHub Pages, а там нет сервера. Sveltia и Decap работают без сервера, но у Sveltia есть русский интерфейс, нормальная работа с двумя языками, сжатие фото при загрузке и вход по токену без дополнительных сервисов. TinaCMS требует облачный аккаунт Tina или свой сервер.

Настройки полей: `public/admin/config.yml`.

## Что умеет

| Раздел | Что можно |
|---|---|
| Статьи | создать, править, фото в тексте и обложка, черновик / опубликовано / корзина, русская и английская версии на отдельных вкладках, SEO-заголовок и описание, адрес страницы |
| Туры | цена, описание, программа, что включено, условия, сезон, фото, FAQ, статус, SEO |
| Занятия | название, описание, длительность, возраст, уровни, фото, статус, SEO |
| Страницы | «О нас», условия бронирования, политика конфиденциальности (RU/EN) |
| Прочее | частые вопросы, переадресации со старых адресов |

Контакты и данные из `content/site.json` пока правятся только в коде.

### Статусы

- **Статьи:** «Черновик» (на сайте не видна), «Опубликовано», «В корзине».
- **Туры и занятия:** «Опубликовано», «Пример» (виден только в preview-сборке), «Снято с публикации», «В корзине».
- **Удаление в админке отключено.** Чтобы убрать страницу, поставьте «Снято с публикации» или «В корзине». Чтобы восстановить, верните «Опубликовано». В разделе списка есть группировка по статусу, так корзину легко найти.
- Если запись всё же удалили из репозитория, её можно вернуть из истории коммитов GitHub (коммиты админки подписаны «CMS: …»).

### Языки

У статей и страниц вверху редактора вкладки «Русский» и «Английский». У туров и занятий каждое текстовое поле содержит две строки: «Русский» и «English». Если английский пустой, страница не появится в EN-версии сайта.

### Адрес страницы (URL)

- Статья: адрес вводится при создании (латиницей) и потом меняется через меню «⋮» в редакторе статьи. Адрес общий для RU и EN, чтобы языковые версии были связаны.
- Тур / занятие: поле «Адрес страницы (URL)».
- Поменяли адрес у опубликованной страницы — добавьте строку в «Прочее → Переадресации» (`/ru/tours/old/` → `/ru/tours/new/`), иначе старые ссылки дадут 404.

### Фото

Загружаются в `public/images/`. При загрузке JPG/PNG автоматически переводятся в WebP и уменьшаются до 2560 px по длинной стороне. Подпись (alt) для новых фото берётся из названия страницы.

## Как дать Артуру доступ

Нужен аккаунт GitHub у Артура (бесплатный) и права на запись в репозиторий.

1. Эмиль: GitHub → `adirov/ski-school` → Settings → Collaborators → Add people → аккаунт Артура (роль Write). Артур принимает приглашение из письма.
2. Дальше один из двух способов входа.

### Способ А: вход по токену (работает сразу, без настройки)

1. Артур: GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token.
2. Repository access: **Only select repositories** → `adirov/ski-school`. Permissions → Repository → **Contents: Read and write**. Срок: 1 год.
3. Скопировать токен, открыть админку → «Войти с помощью токена доступа» → вставить. Браузер запомнит вход.

### Способ Б: кнопка «Войти через GitHub» (удобнее, ~15 минут настройки один раз)

Кнопке нужен маленький посредник для OAuth. Бесплатно на Cloudflare Workers:

1. Развернуть [sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth) кнопкой «Deploy to Cloudflare Workers» из README. Получится адрес вида `https://sveltia-cms-auth.<имя>.workers.dev`.
2. GitHub → Settings → Developer settings → OAuth Apps → New OAuth App:
   - Homepage URL: `https://adirov.github.io/ski-school/`
   - Authorization callback URL: `https://sveltia-cms-auth.<имя>.workers.dev/callback`
3. В Cloudflare у воркера добавить переменные `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` (из OAuth App) и `ALLOWED_DOMAINS` = `adirov.github.io` (плюс свой домен, когда будет).
4. В `public/admin/config.yml` в блок `backend` добавить строку `base_url: https://sveltia-cms-auth.<имя>.workers.dev` и закоммитить.

## Для разработчика

- Пустые поля из админки (`""`, `[]`, `{}`) сайт читает как «не указано» (`clean()` в `src/lib/content.ts`), поэтому незаполненная цена остаётся «по запросу».
- Картинки в контенте — путь `/images/x.jpg` или старый id из `content/media.json`; `img()` понимает оба варианта. Для файлов не из `media.json` размер читается из файла.
- Сохранение через админку переупорядочивает ключи в JSON и убирает пустые поля. Это нормально: сайт получается тот же.
- Локально без GitHub: `npm run dev`, затем http://localhost:3000/admin/index.html → «Работать с локальным репозиторием» (Chrome/Edge) → выбрать папку проекта.
